========================================================================
  依赖清单
========================================================================

本包已把全部依赖打包在内，目标机**无需安装任何东西**。
本文件用于备查：出问题时可以核对版本，将来升级时知道该动哪些。


------------------------------------------------------------------------
 一、自带的 Python 运行时
------------------------------------------------------------------------

  位置      runtime\
  版本      Python 3.10.11 (64 位, AMD64)
  来源      python-3.10.11-embed-amd64.zip（python.org 官方嵌入式发行版）
  许可      PSF License

  为什么锁死 Python 3.10：
      项目依赖的 ICE 原生扩展文件是
          runtime\Lib\site-packages\IcePy.cp310-win_amd64.pyd
      文件名里的 cp310 表示它按 CPython 3.10 的 ABI 编译，
      并且是 64 位的（win_amd64）。所以运行时**必须是 64 位 Python 3.10**，
      换成 3.11、3.9 或 32 位都会 ImportError。

  改动提示：升级 Python 只能升到 3.10.x 系列（已用 3.10.11）。

 三、VC++ 运行库（换机器最容易缺的就是这几个）
------------------------------------------------------------------------

  位置      runtime\  （与 python.exe 同目录，即 app-local 部署）
  文件      msvcp140.dll        来自 VC++ 2015-2022 可再发行组件包
            vcruntime140.dll    （Python 嵌入版自带的）
            vcruntime140_1.dll  （Python 嵌入版自带的）
            concrt140.dll       来自 VC++ 2015-2022 可再发行组件包

  为什么必须带：
      IcePy.cp310-win_amd64.pyd 在导入时会加载 msvcp140.dll 和
      vcruntime140.dll。这两个**不是干净 Windows 自带的**，
      它们由 VC++ 可再发行组件包提供。目标机没装过就会报
          ImportError: DLL load failed while importing IcePy
      这也是"换台机器就报缺依赖"的典型原因。

  说明：放在 python.exe 旁边（app-local）是微软支持的部署方式，
        不需要管理员权限，也不需要目标机安装组件包。

 四、Java 运行时（只给 Allure 报告用）
------------------------------------------------------------------------

  位置      tools\jre8\
  版本      OpenJDK 1.8.0_504 (Temurin, 64 位)
  来源      Eclipse Adoptium（原 Adoptium 项目）
  许可      GPLv2 with Classpath Exception —— 可自由随包分发

  ⚠ 重要：这里**刻意没有用 Oracle JDK**。Oracle JDK 8 的授权条款
    不允许随产品再分发，用它打包会有法律风险。Temurin/Adoptium 是
    同一份 OpenJDK 源码的免费发行版，授权允许分发。

  为什么还需要 Java：
      Allure 命令行程序（allure generate / allure open）是 Java 写的。
      Allure 报告必须通过 HTTP 服务访问（直接打开 html 文件会因为
      浏览器的跨域限制而显示空白），所以需要 Java 来跑这个服务。

 六、本包的 exe
------------------------------------------------------------------------

  位置      启动测试.exe
  来源      由 launcher.py 经 PyInstaller 6.13.0 打包
  许可      launcher.py 为项目自有代码

  说明：
      这个 exe 只是一个启动器（约 30 行标准库代码），不含任何第三方依赖。
      它负责定位包目录、调用 runtime\python.exe 去执行 runner.py。
      真正的执行逻辑在 runner.py 里，是可直接阅读和修改的 Python 源码。

      之所以不把整个测试程序也打成 exe：ICE 的原生扩展 + VC++ 运行库
      在 PyInstaller 打包下很容易出现"开发机能跑、换机器就崩"的问题，
      而带一个真实的 Python 运行环境更稳、也更容易排查。
      exe 采用单文件模式，启动时会解压到临时目录，
      个别杀毒软件可能误报，加白名单即可。

 七、体积构成
------------------------------------------------------------------------

  解压后总计约 164 MB

      runtime\      40 MB     Python + 依赖 + VC++ 运行库
      tools\       119 MB     JRE8 98MB + Allure 22MB
      启动测试.exe    6 MB
      其余           1 MB     源码、用例、文档

  体积大头是 JRE8（其中 lib\rt.jar 一个文件就 60MB，Java 8 本身就这么大）。
  如果将来觉得包太大，可以考虑改用 pytest-html 出报告，
  这样可以整个去掉 tools\ 目录（省 119MB），代价是报告没有 Allure 好看。
