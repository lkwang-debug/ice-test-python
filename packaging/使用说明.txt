========================================================================
  ICE 接口自动化测试 —— 使用说明
========================================================================


【这个包是干什么的】

  免安装的 ICE 接口自动化测试包。目标机不需要装 Python、不需要装 Java、
  也不需要装 VC++ 运行库，解压后改一个配置文件，双击 exe 就能跑完
  276 条用例，并自动在浏览器里打开 Allure 测试报告。

  支持系统：64 位 Windows 10 / Windows 11
  （不支持 32 位系统，不支持 Windows 7）


========================================================================
  ★★★ 执行前必须做的两件事 ★★★
========================================================================

【第一步】在 IceDBProxy 服务器上开通两个端口

  这是最容易漏掉、也最容易误判的一步。请登录 IceDBProxy 所在服务器执行：

      firewall-cmd --zone=public --add-port=20801/tcp --permanent
      firewall-cmd --zone=public --add-port=22000/tcp --permanent
      firewall-cmd --reload

  为什么要开：
      22000/tcp  IceGrid Locator 端口，建立连接用
      20801/tcp  数据通道端口

  ⚠ 端口不通的表现是"连接失败"，不会报任何跟"端口"有关的错误。
    看不懂这条提示的人很容易以为是接口坏了、或者测试包有问题，
    从而往错误的方向排查很久。

  本包已经做了前置检查：连不上会直接给出提示并停止，不会跑出
  276 条失败用例来干扰判断。


【第二步】修改 common\config.py

  用文本编辑器打开包目录下的 common\config.py，只在 SERVER_HOST
  填写实际环境的 IceDBProxy 服务器地址。网关和SSH核查共用此地址。

      SERVER_HOST = "实际服务器IP"

  同一个文件内的 TEST_CONFIG 配置端口、single/dual、设备、房间、
  用户及服务器登录参数。更换环境时核对这些业务身份是否仍有效。
  Excel、报告、Allure和Java路径也在 TEST_CONFIG 内；保存后重新启动。


========================================================================
  怎么执行
========================================================================

  双击包目录下的「启动测试.exe」，等它跑完。

  正常情况你会看到：

      1) 配置摘要（当前连的是哪个地址、用的哪个用例文件）
      2) [预检] 连接成功
      3) 276 条用例的执行过程
      4) 执行结果汇总（通过 / 失败 / 异常 / 跳过）
      5) 浏览器自动打开 Allure 报告
      6) 提示"看完后按回车结束"

  ⚠ 看完报告之前，请不要关掉那个黑色命令行窗口。
    报告是这个窗口里的程序启动的本地服务，窗口一关报告就打不开了。
    看完报告后，在那个窗口里按一下回车，它会自己收尾退出。

  ⚠ 如果预检就没通过（例如端口没开），程序会直接停下来不跑用例。
    这种情况下窗口里会明确写出原因，按提示处理后重新运行即可。

  ⚠ 请先把压缩包完整解压再运行，不要直接在压缩包里双击 exe。
    否则会提示"包不完整"。


========================================================================
  看测试报告
========================================================================

  跑完后浏览器会自动打开报告，地址形如 http://127.0.0.1:5050

  如果浏览器没自动打开，手动在浏览器里输入命令行窗口中显示的地址即可。

  如果提示端口被占用，程序会自动换一个端口，按它显示的地址访问。

  ⚠ 不要用 file:// 的方式直接打开 allure_report\html\index.html。
    Allure 报告需要通过 HTTP 服务访问，直接打开会显示空白或报错。

  ⚠ 报告地址不要发给别人。它指向的是你本机的 127.0.0.1，
    只在你这台机器上能打开。

  报告内容：
      左侧按 sheet 分组的用例树（company / device / room / user / file）
      每条用例可以展开看到「ICE Request」和「ICE Response」附件，
      也就是实际发出去的参数和服务端返回的原始内容，排查问题主要看这里。

  另外，完整的运行日志在 allure_report\run.log，
  报告或控制台信息不够时，把这个文件发出来即可。


========================================================================
  常见问题
========================================================================

Q1. 提示"ICE 服务连不上" / 预检失败
    → 99% 是端口没开。回到上面【第一步】检查 20801/tcp 和 22000/tcp。
    → 其次确认 common\config.py 里的 SERVER_HOST 是否写对。
    → 再确认本机到该服务器网络可达（可以先 ping 一下服务器地址）。

Q2. 提示"无法加载 ICE 运行库"或缺少 msvcp140.dll / vcruntime140.dll
    → 说明 runtime 目录不完整，通常是解压时漏了文件。
      请重新完整解压（用 7-Zip 或 Windows 自带解压，确认 runtime 目录
      下有 python.exe 和一堆 .dll）。
    → 如果确认解压完整仍然报错，可能是 32 位系统，本包不支持。

Q3. 双击 exe 窗口一闪而过
    → 通常是包不完整。请用命令行运行 exe，就能看到具体错误信息：
      按住 Shift 右键包目录空白处 →「在此处打开 PowerShell 窗口」→
      输入  .\启动测试.exe  回车

Q4. 浏览器打开报告是空白页
    → 确认是通过 http://127.0.0.1:端口 访问的，不是 file:// 。
    → 确认启动报告的黑色窗口没有关闭。

Q5. 杀毒软件报警
    → 本包内的 exe 由 PyInstaller 打包，个别杀毒软件会误报。
      测试请求及只读核查发往 common\config.py 里配置的
      ICE 服务器。如被拦截请加白名单。

Q6. 想换一个测试环境
    → 修改 common\config.py 的 SERVER_HOST，并核对设备、房间和用户身份。

Q7. 想改测试用例
    → 用 Excel 打开 data\test_cases.xlsx 直接改，改完保存。
      注意：用例会真实调用服务端接口并修改服务端配置，
      本包内的用例已包含"跑完把配置改回原值"的还原步骤，
      请不要删掉这些还原用例。


========================================================================
  目录说明
========================================================================

  启动测试.exe            双击这个运行
  common\config.py        唯一配置文件，SERVER_HOST只填写一次
  使用说明.txt            本文件
  依赖清单.txt            打包进去的依赖及版本

  runner.py               实际执行逻辑（Python 源码，可查看）
  launcher.py             exe 的源码
  test_api_all.py         测试用例生成与断言逻辑
  method.py               各业务模块的接口封装
  conftest.py             pytest 配置
  common\                 配置读取、Excel 读取、ICE 客户端封装
  generated\              ICE 接口桩代码（自动生成，勿手改）
  ice_files\              ICE 接口定义源文件（供将来重新生成桩代码）
  data\test_cases.xlsx    测试用例数据

  runtime\                自带的 Python 3.10 运行环境（含依赖和 VC++ 运行库）
  tools\jre8\             自带的 Java 运行环境（Allure 报告要用）
  tools\allure-2.18.1\    自带的 Allure 命令行程序

  allure_report\          运行产物
      result\             原始测试结果数据
      html\               生成的 HTML 报告
      run.log             完整运行日志（排查问题时提供这个文件）


========================================================================
  环境要求
========================================================================

  操作系统   64 位 Windows 10 / Windows 11
  内存       建议 2GB 以上可用内存
  磁盘       约 400MB（解压后约 164MB，运行产物另占约 10MB）
  网络       能访问 common\config.py 里配置的 IceDBProxy 服务器
  其他       无需安装 Python / Java / VC++ 运行库


========================================================================
  附：每次执行会做什么
========================================================================

  1. 读取 common\config.py，显示当前配置
  2. 连接 ICE 服务做连通性预检（连不上就直接停，不跑用例）
  3. 读取 data\test_cases.xlsx，动态生成 276 条用例
  4. 逐条调用 ICE 接口并按 Excel 中的预期结果断言
  5. 把结果写入 allure_report\result
  6. 用自带的 Allure + JRE 生成报告到 allure_report\html
  7. 启动本地服务并打开浏览器

  注意：用例是真实调用服务端的，会实际修改 IceDBProxy 的配置数据。
  用例集中已包含还原步骤，执行完整轮次后环境会恢复原状；
  但如果在执行中途强制中断，可能有配置停留在中间状态。
